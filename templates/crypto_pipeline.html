Cryptographic Pipeline
AES-256-CBC · SHA-256 · RSA-2048-PKCS1
Upload Pipeline
1
File Received
Raw file bytes read from upload stream.
Input: multipart/form-data
Output: raw bytes (in-memory)
↓
2
SHA-256 Hash
Compute cryptographic hash of raw file bytes. This is the integrity fingerprint.
Algorithm: SHA-256
Library: hashlib (built-in)
Output: 64-char hex digest
↓
3
RSA-2048 Digital Signature
Sign the hash with the system's private key to create a tamper-evident seal.
Algorithm: RSA-2048, PKCS1v15
Key: 2048-bit, stored in /tmp/evidence_keys
Output: base64-encoded signature
↓
4
AES-256-CBC Encryption
Encrypt the raw file with a random 256-bit key and 128-bit IV derived from the master secret.
Algorithm: AES-256-CBC
Key: derived from MASTER_SECRET (env)
IV: random 16 bytes per file
Output: .enc file stored to Supabase
↓
5
Metadata Stored
All metadata written across three databases simultaneously.
PostgreSQL: evidence record, hash, signature
Neo4j: evidence node + case relationship
MongoDB: audit log, metadata document
Verification Pipeline
1
Retrieve Encrypted File
Fetch .enc file from Supabase storage using stored path.
↓
2
AES Decrypt
Decrypt using stored key/IV to recover original bytes.
Key + IV retrieved from PostgreSQL
Decrypts to original plaintext bytes
↓
3
Recompute SHA-256
Hash the decrypted bytes and compare to stored hash.
If hashes differ → file tampered
Hash mismatch = integrity failure
↓
4
Verify RSA Signature
Verify the stored signature against the computed hash using the public key.
Signature invalid → key mismatch or forgery
Uses system public key from /tmp/evidence_keys
↓
✓
Integrity Verified
Hash match + signature valid = evidence is authentic and unmodified.
